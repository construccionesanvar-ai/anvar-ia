# Mapa de contenido SEO · ia.anvartech.cl

Qué búsqueda responde cada página, para que dos páginas no compitan por la misma
intención (canibalización) y para decidir con criterio si algo nuevo merece una URL.

**Regla principal:** una intención = una página. Antes de crear una URL, busca aquí si
ya existe una página para esa búsqueda. Si existe, mejórala.

## Pares que se parecen y cómo se separan

| Páginas | Cómo se separan |
|---|---|
| `/diagnostico-automatizacion` vs `/diagnostico-ia-empresas` | La primera es gratis, automática y en 2 minutos. La segunda es un servicio pagado con medición en terreno. Se enlazan entre sí con esa explicación. |
| `/automatizacion-procesos-pymes` vs `/automatizacion-procesos-ia` | La primera responde "¿qué se puede automatizar en una pyme y cómo parto?". La segunda vende el piloto e implementación. |
| `/calculadora-roi-automatizacion` vs `/recursos/plantilla-roi-automatizacion` | La calculadora da una estimación en un minuto. La plantilla es para presentar un caso con la inversión real y comparar procesos. |
| `/automatizacion-documental` vs `/casos/automatizacion-documental-retail` | La landing explica la solución (cualquier empresa). El caso cuenta un proyecto concreto con su medición. |
| `/recursos/como-detectar-proceso-automatizable` vs `/recursos/procesos-que-no-deberias-automatizar` | Checklist para decidir vs. lista de trampas comunes. Se enlazan entre sí. |
| `/automatizacion-autocad` vs `/casos#planos-autocad` | La landing explica cómo funciona y sus límites; la ficha del caso muestra el resultado C-03. |

## Enlazado interno

- Cada landing enlaza a: su caso o prueba, 1–2 guías y una herramienta.
- Cada guía enlaza a: la landing de su tema, una herramienta y otra guía.
- La portada enlaza a las landings desde las tarjetas de problemas y a las herramientas desde dos
  tarjetas (la experiencia completa vive solo en su URL: una intención, una página).
- Las guías y el caso largo enlazan al perfil del autor (`/equipo/andres-vargas`).
- El pie enlaza a servicios, soluciones y recursos gratuitos (todas las páginas).
- El QA (`npm run check`) falla si una página indexable queda huérfana.

## Candidatos para contenido nuevo (solo si los datos lo justifican)

No se crea una página por intuición. Cada candidato espera una señal concreta en Search
Console (impresiones sin página adecuada) o preguntas repetidas de clientes:

| Candidato | Señal que lo justificaría | Tipo |
|---|---|---|
| Automatizar PDF a Excel | Consultas con "pdf a excel" en `/automatizacion-documental` o `/automatizar-excel` | Guía o sección |
| Caso C-02 largo (venta en línea) | Tráfico a `/automatizar-cotizaciones` y video del flujo grabado | Caso |
| Informes automáticos | Consultas "automatizar informes / reportes" con impresiones | Sección en `/automatizar-excel` primero |
| Páginas por industria | Un caso real publicado de esa industria (ver `src/datos/industrias.mjs`) | Landing |

## Lo que no se hace

- Páginas por ciudad o comuna con el mismo texto.
- Artículos generados en masa, relleno o palabras clave repetidas.
- Cifras, clientes, testimonios o resultados que no existan.
- Cambiar una URL publicada sin redirección 301 en `vercel.json`.
